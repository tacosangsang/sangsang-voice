# sangsang-voice 작업 진입점

## 먼저 읽을 것

저장소 루트의 [AGENTS.md](../../../AGENTS.md)를 먼저 읽는다. 명령·인자·종료 코드는 [README.md](../../../README.md)를 참고한다.
명령은 저장소 루트에서 실행한다. 아래의 씬·목소리는 예시이므로 요청한 대상으로 바꾼다. 목소리가 정해지지 않았으면 실제 생성 전에 사용자에게 선택을 받는다.

## 요청에 맞는 명령

| 요청 | 명령 |
| --- | --- |
| 대본 점검·컷 길이 넘치는 줄 | `npm run script:lint` |
| 노션 대본을 엄격하게 점검 | `npm run script:lint -- --source notion --strict` |
| 특정 씬 음성 생성 | 확인 후 `npm run dub -- --voice Kore --speaker anchor --scene "S#01"` |
| 영어 음성 | `npm run dub -- --voice Kore --speaker anchor --source notion --scene "S#01" --lang en --dry-run`으로 먼저 확인 |
| dry-run 먼저 | `npm run dub -- --voice Kore --speaker anchor --scene "S#01" --dry-run` |
| 깃허브 업로드 없이 로컬 저장 | 확인 후 `npm run dub -- --voice Kore --speaker anchor --scene "S#01" --no-upload` |
| 테스트·타입·빌드 | 요청 범위에 따라 `npm test`, `npm run lint`, `npm run build` |

CLI의 기본 출처는 저장소 사본이다. 정본 점검을 요청받으면 `--source notion`을 쓴다. 노션 읽기 실패를 사본 결과로 바꿔 보고하지 않는다.
점검 결과를 JSON으로 원하면 `--json`, 정상 줄도 포함하려면 `--all`을 붙인다. 씬·컷 필터는 두 CLI에서 동일하다.
한 목소리는 한 화자만 사용하므로 음성 생성의 `--speaker`는 한 명만 지정하며, 선택된 줄에 화자가 둘 이상이면 `--dry-run`도 종료 코드 1로 거절한다.
영어는 사용자가 확정한 문장이 노션의 영어 대사 칸에 있는지 먼저 확인한다. 사본에 `textEn`이 있어도 정본 승인 여부를 추정하지 않는다. 영어 대사가 없으면 번역을 만들지 말고 사용자에게 확정을 요청한다.

## 실행 전 확인

1. `.env`의 존재와 필요한 칸 이름만 확인한다. 값이나 파일 전체를 출력하지 않는다. `GEMINI_API_KEY`는 실제 생성, `NOTION_TOKEN`은 노션 출처에 필요하다. `NOTION_SCRIPT_PAGE_ID`는 선택이다. CLI의 깃허브 저장에는 실행하는 PC의 `.env`에도 `GITHUB_TOKEN`이 필요하다. 앱 서버에만 설정된 토큰으로는 저장할 수 없다. 칸이 있다는 사실만으로 키가 설정됐다고 단정하지 않는다.
2. 생성 요청에는 먼저 같은 출처·필터·목소리·언어·지시문·업로드 설정으로 `--dry-run`을 실행하고 첫 줄의 저장 대상 또는 꺼진 이유와 표를 사용자에게 보여 준다. TTS 호출과 파일 쓰기는 없지만 노션 출처는 토큰과 네트워크가 필요하며, 깃허브 저장이 켜져 있으면 접속 확인과 목록 읽기를 한다. `--no-upload`는 깃허브 확인·읽기·쓰기를 모두 끈다.
3. 생성 비용·일일 호출 제한이 있으므로 사용자 확인을 받은 뒤에만 `--dry-run`을 빼고 실제 생성한다. 실패했다고 확인 없이 반복 생성하지 않는다.
4. 기존 이름은 건너뛴다. 깃허브 저장이 켜져 있으면 로컬 출력 폴더와 깃허브 목록의 합집합을 쓴다. 앱에서 만든 v1이 있으면 기본은 건너뛰고 `--force`는 v2로 생성한다. 다시 생성 요청이면 `--force`를 dry-run에도 넣어 다음 버전 이름을 보여 준다. 지시문·모델만 바꿔도 기존 이름 판단은 달라지지 않는다.
5. 필요한 키나 도구가 없으면 중단하고 필요한 칸 이름과 설정 방법만 안내한다. 설치나 의존성 추가로 해결하지 않는다.

## 결과 보고

CLI는 PC에 `GITHUB_TOKEN`이 있고 접속 확인·목록 읽기에 성공하면 로컬 저장 뒤 앱과 같은 깃허브 `recordings` 브랜치에 저장한다. 같은 저장소·브랜치를 쓰는 앱의 "저장된 음성" 목록에 보인다. 토큰에는 Contents 읽기·쓰기 권한이 필요하며 브랜치가 미리 있어야 한다. 토큰이 없거나 설정·접속·목록 읽기에 문제가 있으면 이유를 표시하고 로컬 생성만 계속한다. `--no-upload`는 로컬 저장만 한다.

- CLI가 출력한 표를 그대로 전달하고 출처, 선택 범위, 경고, 종료 코드를 함께 보고한다. JSON 요청이면 JSON을 유지한다. 설정 값이 섞였으면 값을 숨긴 뒤 전달한다.
- `script:lint`는 한국어 초당 약 6음절의 예측이다. 영어는 길이를 예측하지 않는다. 문제 줄만 표시하는 기본값과 전체 요약을 구분한다.
- `dub`의 판정은 실제 음성 길이 기준이다. 생성 예정·건너뜀·실패를 생성 완료라고 보고하지 않는다. 저장 폴더와 실제 저장 이름을 함께 알린다.
- 업로드 실패는 로컬 WAV를 유지하며 경고와 "깃허브 저장 실패" 판정, 종료 코드 2를 남긴다. 다음 줄 처리는 계속한다. 업로드만 재시도하는 기능은 없으므로 재실행 시 로컬에 있는 이름은 건너뛴다.
- 초과 컷은 대본이나 컷 길이를 고칠 문제라고 안내한다. 재생 속도로 맞추도록 제안하지 않는다.
- 점검·생성의 종료 코드 0만으로 문제가 없다고 단정하지 않는다. `script:lint`는 `--strict`가 없으면 문제에도 0이고, `dub`은 건너뜀·컷 초과·깃허브 준비 실패 후 로컬 저장에도 0이다. `--batch`는 같은 씬·화자·감정 줄을 묶어 생성하고 무음에서 자른다. 분할 컷과 자르기 실패 원본 모두 깃허브 저장 대상이며, 통째 원본도 첫 줄의 씬 폴더에 저장한다.

## 하지 말 것

- 노션 대본·영어 번역·연기 지시를 지어내거나 사본을 정본보다 먼저 고치지 않는다.
- 프리셋 지시문에 언어를 적지 않는다. `--lang`으로 선택하면 서버가 언어 지시를 붙인다.
- 이미지 프롬프트에 스톱모션·클레이·인형·미니어처·photoreal 같은 실사 연상 단어를 쓰지 않는다. 부정문에도 쓰지 않는다.
- 의존성을 추가하지 않는다.
- 대본 점검·음성 생성·테스트 요청을 이유로 소스를 임의 수정하지 않는다. 불일치는 위치와 근거를 보고한다.
